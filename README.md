화면과 서버가 어떻게 이어지는지 칩으로 바로 확인하고, 의견을 남길 자리를 톡 누른 뒤 한 줄만 적으면 됩니다.

- 리뷰 ID: **`testanchor-real-v1`** (이전 샘플 `testanchor-sample-v1` 판과 구분)
- 구성: `index.html` · `styles.css` · `app.js` (빌드 없음, 의존성 없음)
- 로그인 없음. 아이폰 Safari 와 PC 브라우저에서 바로 열립니다.
- 배포: GitHub Pages — 저장소 `kdonguk/happy-clone` 의 `review-board` 브랜치
  - 주소: **https://kdonguk.github.io/happy-clone/**
  - 바로가기: 흐름도만 보기 `…/happy-clone/#flow`

## 이 판이 담은 것 — 실제 TestAnchor Studio

화면 시안은 실제 앱(`apps/web` — `Studio.tsx` · `LifecycleRail.tsx` · `DiagramView.tsx`)의 구성과 용어를 옮겼고,
서버 흐름도는 실제 파이프라인(`apps/web/app/api/*` → `packages/core/src/services/lifecycle.ts` →
`packages/runners/src/{safety,direct,batch,sql}.ts`)을 따라 그렸습니다.

| 화면 | 실제 앱의 어디 | 담은 것 |
| --- | --- | --- |
| S1 요구사항 · 분석 | 요구사항 카드 → 분석 결과 · 방향 확인 | 요구사항 등록(제목·본문·기준점), 분석 기준점, 제안 변경, **의도 컨펌**(사람 확정) |
| S2 14단계 라이프사이클 | `LifecycleRail` | 5게이트 14단계(G1~G5), 사람 확정 3곳(3·5·10), 실시간 하트비트, 결함·거절 사유와 규칙 키, 단계 메트릭·회차별 기록 |
| S3 연결 · 실행 안전장치 | 상단 모드 배지 + `safety.ts` | 시스템 전환, 코드 인덱스(v·정상·커밋), LLM/러너/영속 배지, `allowWrite`·`WHERE`·허용 테이블·차단 시간대(06:20~08:00 +10분)·LIVE 키 거부, 거절 규칙 |
| S4 테스트 트랙 · 실행 결과 | `TestTrack` + `runs` | 승인 케이스 실행, 실행 스텝(SQL 조회·배치·HTTP), 통과/실패/차단 요약, 결과 계약(스키마·건수·골든·모의/실제), **자가 치유 판정** |
| S5 완료 다이어그램 | `DiagramView` (블루프린트) | 토폴로지 · 데이터 시퀀스 · DB Before/After, 코드 앵커 이동 |

서버 흐름도 노드 13개 — ① 요청 접수 → ② 입력 검증 → ③ 단계 오케스트레이션 → ④ 사람 승인 게이트
→ ⑤ 실행 준비 · 안전장치 → (위반) ⑥ 거절 · 사유 반환 / (통과) ⑦ 실행 분기 → ⑦a 정산 개발 DB 조회 · ⑦b 배치 스케줄러
→ ⑧ 결과 계약 검증 → (실패) ⑧b 자가 치유 판정 → ⑨ 관문 기록 · 영속화 → ⑩ 보고 · 응답.

## 화면 ↔ 서버 연결

화면 시안의 각 카드 아래에 `🔗 서버 흐름: ⑤ 실행 준비 · 안전장치` 칩이,
서버 흐름도의 각 단계 안에 `🖥️ 화면: S3 연결 · 안전장치` 칩이 붙습니다.

- 화면 칩을 누르면 → 흐름도 탭으로 넘어가 그 단계가 **화면 중앙으로 이동하고 파랗게 강조됩니다**.
- 흐름도 칩을 누르면 → 화면 시안 탭으로 넘어가 그 화면 카드로 이동해 강조됩니다.
- 강조 표시는 **다음에 다른 곳을 고를 때까지 남습니다** — 탭을 오가며 봐도 방금 고른 곳이 보입니다.
- 넓은 화면(1024px 이상)은 상단 **`⇹ 나란히 보기`** 로 왼쪽 화면 시안 · 오른쪽 흐름도를 동시에 띄웁니다.
  이때 한쪽의 칩이나 카드를 누르면 반대쪽 대응 요소가 즉시 강조·스크롤됩니다.
- 좁은 화면(아이폰)은 탭 전환 + 칩 원클릭 점프로 동작합니다.
- `📌 핀 찍기` 모드에서도 연결 칩은 이동으로 동작하고, 핀은 칩이 아닌 자리에만 꽂힙니다.

### 매핑 데이터

매핑의 원본은 `index.html` 마크업입니다. 화면과 흐름이 서로를 가리키는지 앱이 스스로 점검합니다
(브라우저 콘솔에서 `__taBoard.audit()`).

| 화면 | 서버 흐름 단계 |
| --- | --- |
| S1 요구사항 · 분석 | ① 요청 접수 · ② 입력 검증 |
| S2 14단계 · 승인 | ③ 단계 오케스트레이션 · ④ 사람 승인 게이트 · ⑨ 관문 기록 · 영속화 |
| S3 연결 · 안전장치 | ⑤ 실행 준비 · 안전장치 · ⑥ 거절 · 사유 반환 |
| S4 테스트 실행 | ⑦ 실행 분기 · ⑦a 정산 개발 DB 조회 · ⑦b 배치 스케줄러 · ⑧ 결과 계약 검증 · ⑧b 자가 치유 판정 |
| S5 완료 다이어그램 | ⑨ 관문 기록 · 영속화 · ⑩ 보고 · 응답 |

- 화면 카드: `data-screen="S4" data-nodes="n7 n7a n7b n8 n8b"`
- 화면 안 세부 영역: `data-region="…"` (이번 판은 카드 단위 매핑)
- 흐름 노드: `g.node[data-node][data-screens][data-chip]`

## 쓰는 법

1. 위 탭에서 **① 화면 시안** 또는 **② 서버 흐름도**를 고릅니다.
2. `📌 핀 찍기` 로 바꾸고 의견을 남길 자리를 **짧게 탭**합니다.
3. 뜬 시트에 한 줄 적고 **저장** (빠른 문구 버튼을 눌러도 됩니다).
4. 오른쪽 아래 **의견 제출** → 피클에게 전달됩니다.
5. `📌 남긴 의견` 목록에서 행을 누르면 그 핀으로 이동합니다. ✏️ 수정 / 🗑 삭제.
6. 헤더의 리뷰 ID 칩을 누르면 프로젝트·버전 ID를 바꿀 수 있습니다(기본 `testanchor-real-v1`).

이전 판(`testanchor-sample-v1`)으로 저장돼 있던 리뷰 ID는 이 판에서 자동으로 `testanchor-real-v1`로 넘어갑니다.
그때 남긴 핀은 이전 키에 그대로 남아 있고, 새 판은 빈 핀에서 시작합니다.

흐름도 탭은 `+ / − / ⤢` 버튼, 두 손가락 확대, 끌어서 이동, 휠 이동(`Ctrl/⌘ + 휠` 확대)을 지원합니다.
핀 모드에서도 끌면 화면이 움직이고, 짧게 탭할 때만 핀이 꽂힙니다.

## 보안

사내 실제 DB 호스트·계정·내부 도메인·테이블 원문은 넣지 않았습니다.
시안과 흐름도는 추상 명칭만 씁니다 — `정산 개발 DB (조회만)`, `사내 정산 API`, `배치 스케줄러`,
`allowWrite`, `WHERE 절 검사`, `차단 시간대 06:20~08:00`, `LIVE 키 거부`.
환경변수 이름·DSN·토큰·사내 URL은 이 보드에 등장하지 않습니다.

  `__taBoard.reanchor()` 로 한 번에 다시 붙일 수 있습니다.
- 배포 후 캐시: `index.html` 의 `styles.css?v=…` · `app.js?v=…` · `rb-version` 을 함께 올려 주세요.
