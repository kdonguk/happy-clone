# TestAnchor 핀 리뷰 보드

동욱 님을 위한 **TestAnchor Studio 실제 화면 ↔ 서버 흐름도 연결 리뷰 보드**입니다.
화면과 서버가 어떻게 이어지는지 칩으로 바로 확인하고, 의견을 남길 자리를 톡 누른 뒤 한 줄만 적으면 됩니다.

- 리뷰 ID: **`testanchor-real-v1`** (이전 샘플 `testanchor-sample-v1` 판과 구분)
- 구성: `index.html` · `styles.css` · `app.js` (빌드 없음, 의존성 없음)
- 로그인 없음. 아이폰 Safari 와 PC 브라우저에서 바로 열립니다.
- 배포: GitHub Pages — 저장소 `kdonguk/happy-clone` 의 `review-board` 브랜치
  - 주소: **https://kdonguk.github.io/happy-clone/**
  - 바로가기: 흐름도만 보기 `…/happy-clone/#flow`

## 이 판이 담은 것 — 실제 TestAnchor Studio

화면 시안은 실제 앱(`apps/web` — `Studio.tsx` · `LifecycleRail.tsx` · `DiagramView.tsx`)의 구성과 용어를 옮겼고,
서버 흐름도는 실제 파이프라인(`apps/web/app/api/*` → `packages/core/src/services/lifecycle.ts` →
`packages/runners/src/{safety,direct,batch,sql}.ts`)을 따라 그렸습니다.

| 화면 | 실제 앱의 어디 | 담은 것 |
| --- | --- | --- |
| S1 요구사항 · 분석 | 요구사항 카드 → 분석 결과 · 방향 확인 | 요구사항 등록(제목·본문·기준점), 분석 기준점, 제안 변경, **의도 컨펌**(사람 확정) |
| S2 14단계 라이프사이클 | `LifecycleRail` | 5게이트 14단계(G1~G5), 사람 확정 3곳(3·5·10), 실시간 하트비트, 결함·거절 사유와 규칙 키, 단계 메트릭·회차별 기록 |
| S3 연결 · 실행 안전장치 | 상단 모드 배지 + `safety.ts` | 시스템 전환, 코드 인덱스(v·정상·커밋), LLM/러너/영속 배지, `allowWrite`·`WHERE`·허용 테이블·차단 시간대(06:20~08:00 +10분)·LIVE 키 거부, 거절 규칙 |
| S4 테스트 트랙 · 실행 결과 | `TestTrack` + `runs` | 승인 케이스 실행, 실행 스텝(SQL 조회·배치·HTTP), 통과/실패/차단 요약, 결과 계약(스키마·건수·골든·모의/실제), **자가 치유 판정** |
| S5 완료 다이어그램 | `DiagramView` (블루프린트) | 토폴로지 · 데이터 시퀀스 · DB Before/After, 코드 앵커 이동 |

서버 흐름도 노드 13개 — ① 요청 접수 → ② 입력 검증 → ③ 단계 오케스트레이션 → ④ 사람 승인 게이트
→ ⑤ 실행 준비 · 안전장치 → (위반) ⑥ 거절 · 사유 반환 / (통과) ⑦ 실행 분기 → ⑦a 대상 DB 조회 · ⑦b 배치 스케줄러
→ ⑧ 결과 계약 검증 → (실패) ⑧b 자가 치유 판정 → ⑨ 관문 기록 · 영속화 → ⑩ 보고 · 응답.


## 시안에 등장하는 이름

공개 저장소이므로 사내 식별자도, 특정 회사·업무 도메인 이름도 쓰지 않았습니다 —
어떤 서비스에든 그대로 연결할 수 있는 **범용 표현**만 씁니다:
`대상 시스템 (개발계)` · `대상 화면` · `대상 API` · `대상 서비스 · 핵심 로직` · `대상 DB (조회만)` ·
`대상 테이블` · `대상 키` · `결과 금액` · `처리 상태` · `대상 배치`.
화면 ID·클래스/메소드명·테이블/컬럼명·배치 잡 ID·커밋 해시도 넣지 않았습니다.

## 화면 ↔ 서버 연결

화면 시안의 각 카드 아래에 `🔗 서버 흐름: ⑤ 실행 준비 · 안전장치` 칩이,
서버 흐름도의 각 단계 안에 `🖥️ 화면: S3 연결 · 안전장치` 칩이 붙습니다.

- 화면 칩을 누르면 → 흐름도 탭으로 넘어가 그 단계가 **화면 중앙으로 이동하고 파랗게 강조됩니다**.
- 흐름도 칩을 누르면 → 화면 시안 탭으로 넘어가 그 화면 카드로 이동해 강조됩니다.
- 강조 표시는 **다음에 다른 곳을 고를 때까지 남습니다** — 탭을 오가며 봐도 방금 고른 곳이 보입니다.
- 넓은 화면(1024px 이상)은 상단 **`⇹ 나란히 보기`** 로 왼쪽 화면 시안 · 오른쪽 흐름도를 동시에 띄웁니다.
  이때 한쪽의 칩이나 카드를 누르면 반대쪽 대응 요소가 즉시 강조·스크롤됩니다.
- 좁은 화면(아이폰)은 탭 전환 + 칩 원클릭 점프로 동작합니다.
- `📌 핀 찍기` 모드에서도 연결 칩은 이동으로 동작하고, 핀은 칩이 아닌 자리에만 꽂힙니다.

## 쓰는 법

1. 위 탭에서 **① 화면 시안** 또는 **② 서버 흐름도**를 고릅니다.
2. `📌 핀 찍기` 로 바꾸고 의견을 남길 자리를 **짧게 탭**합니다.
3. 뜬 시트에 한 줄 적고 **저장** (빠른 문구 버튼을 눌러도 됩니다).
4. 오른쪽 아래 **의견 제출** → 피클에게 전달됩니다.
5. `📌 남긴 의견` 목록에서 행을 누르면 그 핀으로 이동합니다. ✏️ 수정 / 🗑 삭제.
6. 헤더의 리뷰 ID 칩을 누르면 프로젝트·버전 ID를 바꿀 수 있습니다(기본 `testanchor-real-v1`).

### 📖 설명 보기 (읽기용 모드)

상단 모드에서 **`📖 설명 보기`** 를 고르면, 핀이 찍히지 않고 **설명 시트**가 열립니다.
화면 카드·세부 항목·서버 단계 어디를 눌러도 그 자리의
**① 이곳의 역할 → ② 사용자가 하는 일 / 서버에서 일어나는 일 / 나오는 결과 → ③ 다음으로 할 수 있는 것**을
쉬운 말로 보여 주고, 연결된 반대쪽(서버 단계 ↔ 화면)으로 바로 점프하는 버튼을 달아 줍니다.
설명은 화면 5개(S1~S5)·세부 영역 20곳·서버 단계 13개(①~⑩) 모두에 들어 있습니다.
점검은 콘솔에서 `__taBoard.infoAudit()` — `ok: true` 이면 빠짐이 없습니다.

### 🗺️ 전체 동작 안내

탭 줄 오른쪽 **`🗺️ 전체 동작 안내`** 를 누르면 처음부터 끝까지 네 단계로 정리한 안내가 열립니다 —
**1 준비·연결 → 2 요구사항 입력·분석·방향 확정 → 3 구현·배포·테스트 실행(사람 승인 3곳) → 4 실행 결과와 그 결과로 할 수 있는 것**.
각 단계에서 관련 화면·서버 단계로 바로 이동하는 버튼이 붙어 있습니다. 모바일 390px 에서는 버튼이 탭 아래 한 줄로 내려가 넘치지 않습니다.

### 🥒 피클 답변 보기

남긴 의견에 피클이 답한 내용을 보드 안에서 같이 봅니다.

- 의견 카드 바로 아래에 **`🥒 피클 답변`** 말풍선(답변 시각 + 내용)이 붙습니다.
- 답변이 온 의견은 **`💬 답변 완료`**, 아직이면 **`⏳ 대기 중`**, 제출 전이면 **`제출 전`** 배지가 붙습니다.
- 하단 서랍의 **`☁ 제출 기록`** 탭에서 서버에 남은 제출 의견과 답변을 모아 봅니다. `↻ 새로고침` 으로 다시 읽습니다.
  액션바의 `☁ 제출 기록 확인` 을 눌러도 같은 곳이 열립니다.
- 캔버스의 핀이나 `📌 남긴 의견` 행을 누르면 그 의견과 피클 답변이 입력 시트에서 함께 보입니다.

답변은 두 곳에서 합쳐집니다.

| 출처 | 담긴 것 | 수명 |
| --- | --- | --- |
| `replies.json` | 영구 보관. 의견 하나(`opinion`)에 답변(`replies`)을 시간순으로 | 저장소에 있는 한 계속 |
| ntfy 채널 `kind: "reply"` | 실시간으로 도착한 답변 | 무료 채널이라 12시간 |

### 피클 답변 추가하는 법

`replies.json` 의 `opinions` 배열에 항목을 하나 더합니다.

```json
{
  "pin_no": 1,
  "pin_id": "rb-sample-v1-p1",
  "review_ids": ["testanchor-real-v1", "testanchor-sample-v1"],
  "origin_review_id": "testanchor-sample-v1",
  "opinion": {
    "tab": "screen", "target": "S1 대상 카드 · 개발 DB",
    "x": 0.318, "y": 0.129,
    "comment": "개발 db가 뭐야?",
    "submitted_at": "2026-11-15T02:51:45.534Z"
  },
  "replies": [
    { "id": "r-20261115-01", "at": "2026-11-15T07:54:44Z", "by": "피클", "text": "…" }
  ]
}
```

- `review_ids` — 이 답변을 보여 줄 리뷰 ID. 이전 판에서 제출된 의견은 두 판을 함께 적으면 양쪽에서 보입니다.
- `opinion` — 제출된 의견 그대로(탭 · 대상 · 좌표 · 의견 · 제출 시각).
- `replies` — 답변을 시간순으로 쌓습니다. `at` 은 답변 시각(UTC), `text` 는 내용입니다.
- 의견을 찾는 순서: ① `pin_id` ② 의견 문구(양쪽에 문구가 다 있을 때). 둘 다 안 맞으면 답변을 붙이지 않습니다.

실시간으로 답할 때는 ntfy 채널에 아래 JSON 을 POST 합니다.

```json
{"app":"ta-review-board","kind":"reply","review_id":"testanchor-real-v1","pin_no":1,"pin_id":"…","comment":"개발 db가 뭐야?","replied_at":"2026-11-15T07:54:44Z","reply":"…"}
```

`comment` 가 같은 의견에 붙고, 없으면 `pin_no` 로 찾습니다. 점검은 콘솔에서
`__taBoard.replyAudit()` — `ok: true` 이고 `answered`·`renderedReplies` 가 실제 화면과 맞으면 정상입니다.

이전 판(`testanchor-sample-v1`)으로 저장돼 있던 리뷰 ID는 이 판에서 자동으로 `testanchor-real-v1`로 넘어갑니다.
그때 남긴 핀은 이전 키에 그대로 남아 있고, 새 판은 빈 핀에서 시작합니다.

흐름도 탭은 `+ / − / ⤢` 버튼, 두 손가락 확대, 끌어서 이동, 휠 이동(`Ctrl/⌘ + 휠` 확대)을 지원합니다.
핀 모드에서도 끌면 화면이 움직이고, 짧게 탭할 때만 핀이 꽂힙니다.

## 보안

사내 실제 DB 호스트·계정·내부 도메인·테이블 원문은 넣지 않았습니다.

`대상 API`, `대상 배치`, `allowWrite`, `WHERE 절 검사`, `차단 시간대 06:20~08:00`, `LIVE 키 거부`.
환경변수 이름·DSN·토큰·사내 URL은 이 보드에 등장하지 않습니다.

## 고칠 때

- 문구·시안 마크업·매핑(`data-nodes`, `data-region`, `data-screens`): `index.html`

  `__taBoard.reanchor()` 로 한 번에 다시 붙일 수 있습니다.
- 배포 후 캐시: `index.html` 의 `styles.css?v=…` · `app.js?v=…` · `rb-version` 을 함께 올려 주세요.
